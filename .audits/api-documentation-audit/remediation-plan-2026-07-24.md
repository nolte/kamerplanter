## Scope decisions

- **In scope:** all 10 Criticals, the Warnings "CI lint gate", "drift wiring", "contact/license", "servers", and the Suggestion is deferred (auto-generated operationIds are unique and stable; authored IDs would churn generated clients for no functional gain right now).

## Work packages

### WP-A — Reproducible export + app metadata (clears: presence Critical, export-command Critical, info.description Critical, servers/contact/license Warnings)
- `src/backend/scripts/export_openapi.py`: imports `app.main:app`, dumps `app.openapi()` deterministically (sorted keys, stable separators) to stdout or `--out`. Verified to work without a running stack.
- Taskfile target `backend:openapi:export` documented in docs.
- `FastAPI(...)` in `main.py`: add `description=`, `contact=`, `license_info=`, `servers=` (dev localhost + relative production entry, per-environment descriptions).
- Custom `app.openapi()` post-processing: after WP-B, every operation without a `security` key gets an explicit `security: []` — making "deliberately public" machine-readable (clears the public-marking Critical) without touching 14 routers.

### WP-B — Security schemes (clears: securitySchemes/security Critical)
- `common/auth.py`: replace the raw `authorization: str = Header(default=None)` with `HTTPBearer(auto_error=False)` (plus the existing service-account API-key path if present as `APIKeyHeader(auto_error=False)` where applicable). Semantics preserved: optional credentials, manual resolution, Light-Mode/anonymous behaviour unchanged, same error paths.
- Result: FastAPI emits `components.securitySchemes` and per-operation `security` for every op that depends on `get_current_user`/`require_permission`.
- Gate: backend unit tests for auth must stay green.

### WP-C — Error responses per status code (clears: error-response Critical)
- `common/openapi_responses.py`: named response maps built from the project's error envelope reference (documentation-presence only): `AUTH_RESPONSES` (401/403), `CRUD_RESPONSES` (404/409/422), composed dicts per router profile.
- Apply at `APIRouter(responses=...)` level in all 47 routers (router-level responses merge into every operation). Per-op 404-only refinement is out of scope; router-level coverage satisfies "actually-returned status codes documented".

### WP-D — Top-level tags (clears: tags Critical)
- `api/v1/openapi_tags.py`: `OPENAPI_TAGS` list declaring **every** used tag with a one-sentence description; wired via `FastAPI(openapi_tags=...)`.
- Guard: export-time check in `export_openapi.py` warns on used-but-undeclared tags (keeps the list from drifting).

### WP-E — Per-operation contract (clears: summary Critical, parameter-description Criticals, ad-hoc-dict Critical)
- 4 sequential `fullstack-developer` batches over the 47 router modules (disjoint file sets, one agent at a time on the shared worktree):
  1. summaries via `summary=`-kwarg or docstring for all operations missing one (182);
  2. `Path(..., description=...)` for all 164 path params; `description=` for the 19 bare `Query()` params;
  3. `response_model` + small Pydantic response models for the ~20 ad-hoc-dict operations (no behaviour change: models mirror the current dict shape);
  4. batch-local verification: ruff + import check per touched module.

### WP-F — CI lint gate + drift (clears: lint-gate Warning, drift Warning; hardens presence)
- Checked-in snapshot `docs/api/openapi.json` generated by the export script (document presence becomes on-disk, not just runtime).
- `.spectral.yaml` (extends `spectral:oas`, minimal project overrides).
- CI job (in existing backend workflow or new `api-docs.yml`): re-export via script → diff against snapshot (fail on drift) → spectral lint (npx, informational-to-blocking per repo convention: non-required check first).

### WP-G — Docs, verification, PR
- `docs/{de,en}/api/overview.md` (or index): document the export command and the snapshot location; keep DE canonical + EN mirror in sync.
- Verification: run export, assert securitySchemes present, 0 undeclared tags, 0 operations without summary, 0 path params without description, snapshot matches; `task backend:lint` (or ruff+mypy direct) + backend unit tests.
- Conventional-Commits PR to `develop` (English), automerge per repo flow; audit artifact + this plan committed under `.audits/api-documentation-audit/`.
