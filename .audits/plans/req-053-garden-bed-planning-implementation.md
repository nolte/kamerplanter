## 2. Grundsätze für alle Pakete

- **Branching:** je Paket ein Branch `feat/req-053-<slug>` von `origin/develop`, Worktree über `task worktree:add -- feat/req-053-<slug>` (nie `.claude/worktrees/`), frische Top-Level-Session je Lane, max. 3 Lanes parallel (E-08). Schreibende Agenten auf geteiltem Tree sequenziell. Vor jedem Lane-Start `gh pr list --search req-053` gegen Kollisionen prüfen.
- **Autonomie (E-04):** Merge nach grünem Gate + `/code-review` ohne Rückfrage; Prod-Rollout nie (E-07).
- **Service-Signatur:** `*, tenant_key: str` ohne Default; Ownership über `location_ownership` **im Service**, nie als Router-Vorprüfung mit nachfolgendem unscoped Write (Guard-Test `tests/unit/guards/test_keyed_service_writes_take_the_tenant.py` erweitern, nicht umgehen).
- **Geteilte Rechenlogik** (Geometrie, Layout, Pflanzenzustand): Python ist Referenz, TypeScript ist Port, **beide gegen `spec/e2e-testcases/fixtures/garden-plan-vectors.json`** (SSOT, in Welle 1 anlegen). Kein Test darf die Regel über einen anderen Pfad erreichen als die Produktion.
- **Enums nur additiv** (`TaskCategory`, `LocationType`-Seeds, `NutrientDemand`): Retirement crasht den Start.
- **Pro Welle:** grünes Quality-Gate (`task check`), `/code-review`, bei Frontend-Änderungen die 3-Agent-Kette (Docs, UI-Review, Tests), PR gegen `develop` mit `automerge`-Label erst nach Review; Trailer `Co-Authored-By: Claude Fable 5.1`.
- **Bundle:** 0 KB Initial-Zuwachs; `bundle-budget.json` → `routeChunks.gardenPlanner: 120`.
- **Spec-Pins:** jedes Paket nennt im PR-Body die GP-IDs; `TC-REQ-053.md` bleibt die E2E-Quelle (TC-053-001…044, conftest-Marker `req053`).

## 6. Risiken und Fallen (aus Memory, auf dieses Vorhaben angewandt)

- **Migration M1 auf Bestand**: Alt-Slots ohne `position`-Semantik (Zelt-Raster) bekommen `pitch_m 0,30` als Annahme → Dry-Run-Report **vor** Prod-Lauf lesen; `GP-ACC-036` prüft die Ableitung. Proxmox-/Prod-Deploy-Falle: `:latest`-Pin, Rollout erst nach Migration-Report.
- **Enum-Erweiterung `TaskCategory`**: nur additiv; Frontend-`enums.taskCategory.*` i18n für 16 neue Werte DE/EN **im selben PR**, sonst `i18n-completeness-checker` rot.
- **Guard-Test für Service-Signaturen**: neue Services (`garden_plan_service`, `care_event_service`, `planting_layout`) in die Liste von `test_keyed_service_writes_take_the_tenant.py` aufnehmen — sonst ist der Guard inert für genau die neuen Schreibpfade.
- **Geteilte Vektoren**: ein pytest und ein vitest lesen dieselbe Datei; ein Test, der die Vektoren inline kopiert, zertifiziert nichts.
- **Bundle-Budget**: `gardenPlanner`-Chunk über `routeChunks` begrenzen; Budget-Gate blockiert Automerge — nie das Budget anheben, Chunk splitten.
- **E2E-Timing**: Debounce 300 ms auf „Erledigt", 300 ms Hover, 8 s Snackbar → Waits an Zustand (`aria-live`-Text, Request-Abschluss) ankern, keine Retry-Schleifen.
- **Lokale Tests**: Backend-pytest über `.venv/bin/python`; `localhost:8529` maskiert DB-berührende Unit-Tests → Transaktions-Tests als Integration kennzeichnen.
- **Renovate-/Parallel-Lanes**: Migrationsnummer erst beim Branch-Start fixieren; bei Kollision Nummer anheben, nie umnummerieren nach Merge.
- **Review-Agenten ohne Write**: Berichte von `agrobiology-requirements-reviewer` ggf. selbst ablegen.
